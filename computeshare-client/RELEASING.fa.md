# انتشار نسخهٔ جدید ComputeShare (راهنمای ساده)

این راهنما برای هر دو مخزن است: **computeshare-client** (`csnode`، `cs`، نصاب) و **computeshare-server** (`csbroker`). ساخت فایل‌ها «تکرارپذیر» است: هر کس همان نسخه را بسازد دقیقاً همان فایل‌ها و همان `SHA256SUMS` را می‌گیرد.

> **وضعیت فعلی:** ساخت، چک‌سام، انتشار پیش‌نویس و **امضای نسخه (کارت 012)** کار می‌کند. نصاب Linux و `csnode install` روی Windows هر چیزی را که با کلید `internal/release/release.pub` امضا نشده باشد رد می‌کنند. تا وقتی این فایل خالی است، هیچ نصبی انجام نمی‌شود.

> **اسکریپت انتشار:** روی کامپیوتر صاحب پروژه، داخل مخزن، فقط `scripts/release.sh 0.2.0` را بزنید. تست می‌گیرد، همهٔ فایل‌ها را می‌سازد، رمز کلید را از شما می‌پرسد و امضا می‌کند، برچسب می‌زند و یک انتشار پیش‌نویس در GitHub می‌سازد. خودتان بعد از دیدن، آن را منتشر می‌کنید. اجرای آزمایشی بدون امضا: `scripts/release.sh 0.2.0 --no-sign --no-upload --allow-dirty --reproducible-check`.

## قانون‌ها

1. **کلید خصوصی امضا فقط روی لپ‌تاپ صاحب پروژه** می‌ماند (و یک نسخهٔ پشتیبان روی فلش آفلاین). هیچ‌وقت روی سرور، باکس ربات، CI یا GitHub نه.
2. GitHub فقط نسخهٔ **پیش‌نویس** می‌سازد؛ انتشار نهایی را خود صاحب پروژه بعد از امضا انجام می‌دهد.
3. سرور و کلاینت با **یک برچسب یکسان** مثل `v0.2.0` منتشر می‌شوند.

## ۱. آماده‌سازی

تست‌ها را اجرا کنید: در کلاینت `make vet test`، در سرور `make vet test e2e`، و روی یک سیستم آزمایشی با Incus دستور `sudo computeshare-client/e2e/system_e2e.sh` (باید آخرش «0 failed» باشد).

## ۲. برچسب زدن

```bash
git -C computeshare-client tag -a v0.2.0 -m v0.2.0 && git -C computeshare-client push origin v0.2.0
git -C computeshare-server tag -a v0.2.0 -m v0.2.0 && git -C computeshare-server push origin v0.2.0
```
GitHub خودش فایل‌ها و `SHA256SUMS` را می‌سازد و یک انتشار پیش‌نویس درست می‌کند.

## ۳. امضا روی لپ‌تاپ خودتان (کارت 012)

هر نسخه: `SHA256SUMS` را دانلود کنید، `cs release sign SHA256SUMS` بزنید، فایل `SHA256SUMS.sig` را به انتشار پیش‌نویس اضافه و منتشر کنید.

یک بار، قبل از اولین نسخهٔ امضاشده: `cs release keygen` بزنید، `release.key` را فقط روی لپ‌تاپ و یک فلش آفلاین نگه دارید، و `release.pub` را در `internal/release/release.pub` بگذارید و **قبل از تگ زدن** commit کنید.
نصاب Windows را **بعد از امضا** بسازید تا `SHA256SUMS` و `SHA256SUMS.sig` کنار rootfs باشند. فهرست imageهای میرور (`images.lock`، کارت 014) را هم همین‌طور امضا کنید.
آزمون کامل نصاب: `e2e/installer_sig.sh`.

## ۴. میرور و سرور

فایل‌ها را در `/srv/mirror/csnode/` روی سرور بگذارید تا نصب از ایران سریع باشد. به‌روزرسانی سرور طبق بخش «Upgrade» در `docs/DEPLOY.fa.md` و فقط با تأیید صاحب پروژه.
