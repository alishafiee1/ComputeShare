# نصب نود ComputeShare (راهنمای ساده)

با نصب نود، بخشی از توان سیستم شما (CPU، RAM، کارت گرافیک) در یک **فضای جدا** در اختیار کسانی قرار می‌گیرد که رمز آن فضا را به آن‌ها بدهید. آن‌ها **به فایل‌های شما، شبکهٔ خانه و خود سیستم دسترسی ندارند**. فضا اینترنت دارد. هر وقت خواستید خاموشش می‌کنید.

قبل از شروع لازم دارید:
- یک **توکن عضویت** از مدیر سرور
- یک رمز حداقل ۱۲ حرفی برای کاربر فضا

## لینوکس

یک ترمینال باز کنید و این را بزنید:
```bash
curl -fsSL https://node.n3xus.ir/install.sh | sudo sh
```
نصاب فایل‌ها را دانلود می‌کند، امضای نسخه و `SHA256SUMS` را چک می‌کند (فایل بدون امضا یا تغییرکرده نصب نمی‌شود) و بعد چند سؤال می‌پرسد:

1. موافقت (بنویسید `yes`)
2. چقدر CPU، RAM و دیسک بدهید (خالی = بدون محدودیت)
3. کارت گرافیک را به اشتراک بگذارید؟
4. **آدرس سرور** — فقط Enter بزنید تا `https://node.n3xus.ir` انتخاب شود
5. نام نود (مثلاً `myBrotherPc`)
6. نام کاربر فضا (پیش‌فرض `user`؛ دسترسی sudo دارد، ورود root بسته است)
7. رمز (دو بار)
8. توکن عضویت
9. محدودیت پهنای باند (پیشنهاد `20Mbit`) و سقف حجم روزانه (پیشنهاد `20GB/day`)؛ خالی = نامحدود

در آخر بزنید تا با روشن شدن سیستم خودکار اجرا شود:
```bash
sudo csnode service install
```

## ویندوز ۱۰ و ۱۱

فایل `csnode-setup-....exe` را با «Run as administrator» اجرا کنید. ممکن است یک بار ری‌استارت بخواهد؛ بعدش خودش ادامه می‌دهد. بعد در PowerShell بزنید `csnode setup` و همان سؤال‌ها را جواب دهید.

### ویندوز: ادمین لازم هست یا نه؟

فقط این کارها ادمین می‌خواهند: روشن کردن WSL2 (وقتی از قبل نصب نیست)، تسک شروع موقع بوت (با SYSTEM) و اضافه کردن به PATH کل سیستم. اگر WSL از قبل نصب است، در پنجرهٔ اول «فقط برای من» را انتخاب کنید (یا `/CURRENTUSER` بدهید): بدون ادمین نصب می‌شود و نود **موقع ورود شما به ویندوز** بالا می‌آید، نه موقع بوت. اگر WSL نصب نباشد، نصاب در صفحهٔ بررسی سیستم می‌ایستد و می‌گوید با ادمین اجرا کنید. (حالت بدون ادمین هنوز روی ماشین دوم تست نشده.)

### ویندوز: نصب بی‌صدا (بدون پرسش)

در PowerShell و پوشهٔ نصاب:

```powershell
.\csnode-setup-<version>.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG="$env:TEMP\csnode-setup.log" `
  /ACCEPT /SERVER=https://node.n3xus.ir /TOKENFILE=C:\secrets\token.txt /NODENAME=my-node-01 `
  /WSLDIR=D:\ComputeShare /SPACEUSER=guest /SPACEPASSFILE=C:\secrets\pass.txt
echo $LASTEXITCODE
```

پارامترها: `/ACCEPT` (اجباری، یعنی شرایط را قبول دارید)، `/SERVER`، `/TOKEN` یا `/TOKENFILE` (فایل امن‌تر است)، `/NODENAME`، `/WSLDIR`، `/SPACEUSER`، `/SPACEPASS` یا `/SPACEPASSFILE` (حداقل ۱۲ نویسه) و/یا `/SPACEKEY` (کلید عمومی ssh)، و اختیاری `/CPU` `/MEMORY` `/DISK` (نداده باشید = همان مقدار امن پیشنهادی). `/CURRENTUSER` یعنی بدون ادمین، `/ALLUSERS` یعنی با ادمین.

کد خروج: `0` موفق، `20` پارامتر نامعتبر یا جاافتاده، `21` فراموشی `/ACCEPT`، `22` ویندوز قدیمی یا مجازی‌سازی خاموش، `23` WSL نیست و ادمین هم نیستید، `30` نصب WSL یا سیستم لینوکسی خراب شد، `31` راه‌اندازی نود خراب شد، `32` نام نود تکراری، `33` سرور در دسترس نیست، `3010` ویندوز باید ری‌استارت شود و همان دستور دوباره اجرا شود. دلیل شکست در `%LOCALAPPDATA%\ComputeShare\logs\install-result.log` نوشته می‌شود (جزئیات در `install.log` و `setup.log` همان پوشه).

در نصب عادی (با پنجره) اگر شکست بخورد، صفحهٔ آخر قرمز است و «نصب ناموفق بود» با دلیل و مسیر فایل گزارش نشان می‌دهد.

## بعد از نصب

- **پنل ساده:** `sudo csnode panel` را بزنید و لینکی را که نشان می‌دهد روی همین سیستم باز کنید. آنجا وضعیت اتصال، روشن/خاموش کردن اشتراک، محدودیت‌ها و افراد وصل‌شده را می‌بینید و می‌توانید کسی را فوراً قطع کنید. لینک را به کسی ندهید.
- خاموش/روشن کردن اشتراک: `sudo csnode share off` و `sudo csnode share on`
- وضعیت: `sudo csnode status`
- حذف کامل: `sudo csnode leave --purge`

اگر سرور «تأیید مدیر» را روشن کرده باشد، نصب می‌گوید نود «در انتظار تأیید» است؛ بعد از تأیید مدیر، خودکار وصل می‌شود.

## دیگران چطور وصل می‌شوند

```bash
ssh -J join@node.n3xus.ir:2222 user@myBrotherPc
```
یا یک بار `cs setup` (دعوت لازم نیست و همهٔ آماده‌سازی را یک‌جا انجام می‌دهد)، و بعد فقط `ssh myBrotherPc.cs`. کد fingerprint که آخر نصب نشان داده شد را به آن‌ها بدهید تا مطمئن شوند به نود واقعی وصل شده‌اند.

## کاربر داخل فضا و دسترسی `sudo`

کاربر داخل فضا (`user`) عمداً توی گروه `sudo` است و بدون رمز `sudo` می‌زند. دلیلش این است که فضا یک کانتینر جداست: مهمان داخل آن هر چیزی نصب می‌کند (مثلاً `apt install`) ولی به سیستم خود تو دست نمی‌رسد؛ سقف پردازنده، رم و دیسک هم از بیرون اعمال می‌شود. پس `sudo` داخل فضا یعنی «مدیر فضای خودش»، نه «مدیر لپ‌تاپ تو». گزینهٔ «کاربر بدون `sudo`» فعلاً وجود ندارد.

## چند کاربر، هر کدام با فضای خودش (اختیاری)

یک بار با `sudo csnode users migrate` روشنش کنید (فضای فعلی مال کاربر خودش می‌شود) و بعد کاربر بسازید:
```bash
sudo csnode users add ali --key-file ali.pub      # یا بدون --key-file تا رمز بپرسد
sudo csnode users ls
```
هر کاربر بار اول که وصل شود (`ssh ali@myBrotherPc.cs`) کانتینر خودش را می‌گیرد و فایل‌هایش بین دفعه‌ها می‌ماند. فضای بیکار بعد از ۳۰ دقیقه خاموش می‌شود (`idle_stop`) و حداکثر ۳ فضا هم‌زمان روشن‌اند (`max_running_spaces`). با روشن کردن این حالت host key عوض می‌شود؛ خط تازهٔ `cs add` را از `csnode status` برای کاربرها بفرستید.
